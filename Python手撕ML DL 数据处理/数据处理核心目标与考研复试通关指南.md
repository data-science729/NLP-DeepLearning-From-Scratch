## 一、 工具定位大观：何时用什么？

初学者最容易对 MySQL、Pandas、PySpark 产生认知混乱。它们的分工与定位如下：

| 工具 | 角色比喻 | 擅长数据量级 | 核心应用场景 | 什么时候选它？ |
| :--- | :--- | :--- | :--- | :--- |
| **MySQL** | **仓库保险柜** | MB ~ 几 GB | 在线事务（OLTP），高频并发增删改查 | 生产系统中需要持久化、强一致性保证（如用户注册、订单） |
| **Pandas** | **个人精密手术台** | 几 MB ~ 几 GB（受限于单机内存） | 单机探索性分析（EDA）、特征工程、小模型前置处理 | 本地做实验、写论文、打 Kaggle/天池比赛、复试上机 |
| **PySpark** | **现代工业流水线** | 几十 GB ~ TB / PB 级 | 分布式海量数据离线批处理（OLAP） | 单机内存装不下、几十台/上百台服务器协同清洗海量日志或语料 |

> **真实工作流**：
> 业务系统产生数据存入 **MySQL** $\rightarrow$ 历史海量数据用 **PySpark** 分布式批量清洗与抽样 $\rightarrow$ 提取关键子集到本地用 **Pandas** 深度分析与建模。

## 二、 Pandas 刷题与数据处理“通用代码骨架”

绝大多数二维表格数据处理，都可以按照固定的 **4 步流转法** 书写：

```python
import pandas as pd

def process_data(df1: pd.DataFrame, df2: pd.DataFrame) -> pd.DataFrame:
    # 步骤 1: 关联 / 对齐（多表时必做：merge / concat）
    # 步骤 2: 过滤 / 筛选（核心条件：布尔掩码 / query / isin / isna）
    # 步骤 3: 聚合 / 计算 / 去重（若需要：groupby / agg / drop_duplicates / sort_values）
    # 步骤 4: 投影与格式整理（选列、改名：[['col']] / rename）
    return result_df
```

### 必记避坑守则
1. **单括号 vs 双括号**：
   - `df['col']` 返回的是 `Series`（一维序列）。
   - `df[['col']]` 返回的是 `DataFrame`（二维表格）。力扣与系统接口通常要求返回 DataFrame。
2. **布尔索引的位运算**：
   - 逻辑非用 `~`（不可用 `not`）。
   - 逻辑与用 `&`，逻辑或用 `|`，**每个子条件必须用括号包围**：`(df['a'] > 1) & (df['b'] < 5)`。
3. **空值判断绝对不可用 `== None`**：
   - 必须使用 `.isna()` 或 `.notna()`。
4. **列名重命名**：
   - `.rename(columns={'old_name': 'new_name'})`，注意是 `columns`（带 `n`），默认返回新表。

## 三、 考研复试与科研核心方法论（口试高频核心）

导师在复试中**绝不会考你 API 怎么拼**，考察的是**数据清洗与实验设计规范**。

### 1. 缺失值（Missing Values）处理
- **删除法**：缺失比例极低（< 1%）且总体样本量充裕时。
- **统计填补**：
  - 数值型：优先使用**中位数**（抗偏态与异常值）或均值；
  - 类别型：使用**众数**或标记为单独的类别（如 `'Unknown'`）。
- **模型预测插补**：使用 KNN、随机森林或多重插补（MICE）利用相关特征预测填补。

### 2. 异常值（Outliers）处理
- **正态分布**：采用 **$3\sigma$ 原则**（均值 $\pm 3$ 倍标准差之外的视作异常）。
- **偏态 / 通用分布**：采用 **箱线图（IQR 四分位距法）**：
  - 下界：$Q_1 - 1.5 \times \text{IQR}$
  - 上界：$Q_3 + 1.5 \times \text{IQR}$
- **处理方式**：盖帽法（截断至阈值边界）、剔除或单独建立异常检测特征。

### 3. 类别不平衡（Class Imbalance）
- **数据层面**：过采样（如 SMOTE 合成少数类）、欠采样（降采样多数类）。
- **算法层面**：损失函数加权（Class Weight）、采用 Focal Loss 抑制简单负样本。
- **评估指标（高频坑点）**：
  - **切忌只看准确率（Accuracy）**！99:1 的样本全猜多数类准确率也有 99%，毫无意义。
  - **必须汇报**：PR-AUC、F1-Score、Recall（召回率）。

### 4. 导师高频必杀题：数据泄露（Data Leakage）
- **核心问法**：“你在做特征归一化 / 标准化时，是在划分数据集之前做，还是之后做？”
- **红线原则**：**必须先划分训练集和测试集！**
- **标准回答**：只在训练集上 `fit` 得到均值和标准差，再用这套参数去 `transform` 测试集。在数据预处理阶段绝不能提前引入测试集的全局分布信息。

## 四、 NLP / 大模型（LLM）专属：文本预处理要点

针对自然语言处理方向，重点掌握以下文本处理管线：

### 1. 分词（Tokenization）与词表
- **传统 NLP**：基于词典与统计（jieba 分词），未登录词（OOV）需通过 `<UNK>` 占位。
- **现代大模型**：基于子词切分算法，最核心为 **BPE（Byte-Pair Encoding，字节对编码）** 和 WordPiece。通过频次合并高频子词，彻底解决 OOV 难题。

### 2. 文本清洗与停用词取舍
- **无用噪声过滤**：正则表达式去除 HTML 标签、特殊 URL、非打印字符、乱码与冗余空白。
- **停用词的辩证使用**：
  - 做传统文本分类、TF-IDF、词袋模型时，通常过滤停用词以降低维度；
  - 做基于 Transformer / BERT / LLM 的预训练与微调时，**坚决不滤停用词**，必须保留自然语言完整的上下文句式结构。

### 3. 长度对齐与截断策略
- **长文本截断**：
  - 不建议盲目仅保留前 512 词；
  - 推荐 **Head + Tail Truncation（头部截取 + 尾部截取拼接）**，保留新闻/论文的核心背景与结论。
- **Padding 策略**：Batch 内动态填充（Dynamic Padding），避免对齐到全局最大长度造成大量无用计算。

### 4. 文本数据增强（Data Augmentation）
- **回译法（Back-translation）**：中文 $\rightarrow$ 英文 $\rightarrow$ 中文，生成同义变体。
- **EDA 技术**：同义词替换、随机插入、随机交换位置、随机删除。

## 五、 复试高情商应答公式与话术模板

> **导师提问**：“在你的毕设 / 项目中，数据预处理是怎么做的？遇到过什么问题？”

**高分回答结构（三步法）**：
1. **第一步（探索性分析）**：
   “老师，在拿到原始数据后，我首先进行了探索性数据分析（EDA），检查各字段的缺失率、分布偏态以及可能存在的异常值。”
2. **第二步（规范清洗与防泄露）**：
   “针对缺失值，我依据特征分布进行了中位数/众数合理填补。在特征工程和归一化处理时，我**严格遵循防止数据泄露的原则**，先划分训练集与测试集，仅在训练集上拟合统计参数。”
3. **第三步（结合专业任务细化）**：
   “对于后续的文本建模任务，我进一步做了正则噪声去重、BPE 子词分词以及头尾截断对齐，确保送入模型的数据既整洁又保留了完整的上下文信息。”
